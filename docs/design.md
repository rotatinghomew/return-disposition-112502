# 设计说明：可比归因与仓配处置

## 能力总览

```
input_contract → model → dictionary / catalog → evidence → cohorts → metrics
                                                              ↓
                                              disposition ← trace → pipeline
```

## 证据分层（evidence.py）

自由文本、标准原因、质检结论是三层证据，分别记录、不互相覆盖：

- **标准原因（客服选项）**：按退货请求时点生效的原因字典版本解释。
- **自由文本**：只做启发式原因族提示（`free_text_hint`），永远标记为未核实，
  不与标准原因混计。
- **质检结论**：功能、外观两个维度都是三态（`ok` / `issue` / `unknown`）。
  - 缺少到货检验 = 未知，**不能**记为无缺陷；
  - 外观判损坏**不能**覆盖未检的功能项；
  - 尺寸/描述类原因质检无法直接验证，`verified_by_inspection` 只对损坏类成立。

归因输出 `Attribution`：原因族、依据层、是否经质检核实、未决项说明；
三层都无内容时记为 `unattributable`，进入「仍无法归因」比例。

## 版本化解释（dictionary.py / catalog.py）

- 原因字典按版本生效区间解释历史代码；请求时点没有该代码时回退到
  引入该代码的版本，并标记「跨版本回退，不可直接比较」。
- 版本间映射分 `one_to_one`（可直接比较）与 `split`（只能族级比较）。
- 商品按订单时点取生效版本，批次标识 `sku@version`；无版本覆盖时显式
  标记而不是套用现行规格。SKU 合并通过 `merged_from` 记录谱系，
  `lineage_key` 让被合并 SKU 归入合并后 SKU 继续比较。

## 可比队列与指标（cohorts.py / metrics.py）

- 队列 = 渠道 × 批次，是可比分析的最小范围；分子分母都用订单机会
  （售出件数），不是订单数。
- 重复开单（`supersedes` 链路或 `cancelled`）不计入分子分母但保留记录；
  活跃退货超过订购数量时标记疑似未闭合的重复开单。
- 跨期比较用直接标准化：以最早期的渠道 × 批次结构为参考，
  把粗率差分解为结构效应 + 率效应（残差单列），避免把促销期
  订单结构变化误读为质量恶化；销量 <5 的单元标记低置信。
- 复购影响：退货客户 vs 未退货客户在 90 天窗口内的复购率；
  窗口未关闭的客户删失，不计入比例。

## 处置建议与重计划（disposition.py）

- 动作由证据三态推出：功能不合格 → 隔离；功能未检 → 隔离 + 质检前置；
  外观损坏 → 翻新；已拆封正常 → 重封装；未拆封正常 → 再售。
- 约束逐条记录在建议上：库位容量（超限降级为隔离并注明）、质检能力
  （积压与产能）、已承诺换货（占用可售库存）、采购到货日期
  （晚于承诺期限 = 履约冲突告警）。
- 重计划规则：
  - 已执行处置、已完成退款、已发出换货是事实，**不可静默改写**；
    新证据冲突只发告警；
  - 未执行（`planned`）处置可被新建议取代，被取代者保留审计痕迹
    （`supersedes` 链路）。

## 追溯（trace.py）

- `explain_recommendation`：从一条建议回查订单事实、三层原因证据、
  商品版本（含合并谱系）、容量/承诺/到货约束与告警。
- `batch_followup`：同一 SKU 相邻批次间按原因族比较；字典换版时只做
  族级比较并显式标记；族样本不足时给出「样本不足，不能确认」，
  判断后续批次是否支持原先的质量判断。

## 已知边界

- 自由文本提示是关键词启发式，仅用于演示分层，不能替代人工标引。
- 合成资料样本量小，所有比例都带低置信标记；指标实现按机制正确性
  设计，不接外部统计库。
- 批次直接取商品版本（`sku@version`），若后续接入真实采购批次，
  只需替换 `catalog.definition_at` 的批次来源。
